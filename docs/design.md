# 设计与边界

## 定位

`linux-inspector` 面向客户现场安装包选型与基础排障，仅采集通用 Linux 运行环境；不是基准测试工具、漏洞扫描器或硬件巡检系统。

## 兼容性原则

- 不以单个命令是否存在判定 Linux 发行版家族。
- `ID_LIKE` 只是发行版声明的兼容关系，不能证明任意软件包可用。
- 包数据库统计仅为诊断辅助；不能按 RPM/DPKG 数量直接判断原生包管理器。
- `uname -m` 返回内核架构（如 `aarch64`），Debian 软件包架构可能为 `arm64`。
- `ldd` 对非 glibc 环境不等同于 glibc 版本；优先使用 `getconf GNU_LIBC_VERSION` 提供额外依据。
- `systemctl` 可执行文件存在不代表 PID 1 是 systemd。
- `java` 在 PATH 中不保证安装了 `javac`；`javac` 的存在可作为 JDK 的初步判断。

## 隐私和安全

只读执行、无需 root、无网络上传。默认不读取 machine-id、网卡 IP、进程环境变量、数据库连接串和用户文件。报告仍需由用户审核后再对外分享。

## 未来演进（按需）

可增加 `--format json`、`--modules`、locale/glibc ABI 检查、最小依赖兼容性检测，但应优先保持默认运行逻辑简单稳定。

## 服务检查扩展方向

当前版本只实现系统环境检查，尚不包含服务检查。后续根据实际需要，可将 PostgreSQL、HGDB、Patroni 和 etcd 检查分别放入独立模块，由入口脚本显式调用；模块仅负责各自的只读检查，缺失命令或权限时报告原因。默认不连接数据库、不读取凭据、不自动启停或修改服务。具体接口和依赖等有真实需求时再确定。
